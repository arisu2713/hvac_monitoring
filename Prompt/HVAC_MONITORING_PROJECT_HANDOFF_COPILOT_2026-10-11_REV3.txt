4. THE `hvac_monitoring` REMOVAL — CONFIRMED, AND A CORRECTION
================================================================================

USER-REPORTED CONTEXT (as given):
  "hvac_monitoring has been deleted; the poller was updated afterwards; the Web App is
   unaffected."

AUDIT RESULT — split verdict, and this is the most important finding of the revision:

  (a) It was a DATABASE, not a table — VERIFIED.
      MariaDB error 1049 "Unknown database 'hvac_monitoring'" is raised ONLY for an
      unknown schema. It appears 292 times in the Daikin poller's log. Multiple source
      files also configure it as a `database`/`DB_NAME` value, never as a table.
      NOTE: a naive existence probe as hvac_web is INCONCLUSIVE — and the tempting
      reading of it ("1142, not 1049, so it must exist") is exactly backwards. Control
      probe: mysql, performance_schema and sys all PROVABLY EXIST on this server and all
      return the identical 1142 "SELECT command denied" with 0 information_schema.SCHEMATA
      rows, same as a deliberately fake schema name. MariaDB does not disclose schema
      existence to an account with no privilege on it. The 1049 error from the poller
      (which DID hold privileges) is the decisive evidence. Recorded in
      docs/DATABASE_INVENTORY.md §3.2 so a future audit does not repeat the dead end.

  (b) The Web App IS unaffected — VERIFIED.
      config.php points at hvac_current; no api_*.php, no SQL file, and no tracked
      documentation in this repo ever referenced the hvac_monitoring DATABASE. The only
      repo mentions of the string are the FILESYSTEM PATH C:\xampp\htdocs\hvac_monitoring
      (the project folder itself), plus one code comment in api_room.php:141 explaining
      why it deliberately does NOT join hvac_monitoring.daikin_points.

  (c) "The poller was updated" — TRUE FOR THREE POLLERS, FALSE FOR A FOURTH.
      Azbil BACnet  — migrated. History write removed (commit ad49d98); now writes
                      hvac_current.* only.                                            [VERIFIED]
      EF            — migrated. Zero hvac_monitoring references in the active engine
                      (commit deb638e).                                               [VERIFIED]
      HNX G8        — migrated. Live data confirms.                                  [VERIFIED]
      DAIKIN        — *** NOT MIGRATED. STILL BROKEN. ***                            [VERIFIED]
                      See section 5.

  (d) Objects that lived in hvac_monitoring (historical, all gone):
      ai_readings, bi_readings, acc_readings, daikin_readings, ef_readings,
      hnx_g8_readings, points_legacy. NONE exist in hvac_current, and none were
      recreated — as instructed. Note ef_readings held ~1,054,048 rows
      (monitoring_ef/ef_migration_plan.md:28); that history is permanently lost.

  (e) Stale references to the dropped database REMAIN in source outside this repo.
      They are catalogued with file:line in docs/DATABASE_ARCHITECTURE.md §6 and §9.
      Nothing in this repo was changed to fix them (out of scope for a read-only audit).

  indistinguishable from a steady reading. Fixing the indicator (using the read_at the
